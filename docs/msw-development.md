# MSW Development Guide

Mock Service Worker (MSW) allows you to intercept and mock API calls in the browser for testing and development.

## Quick Start

### First Time Setup

```bash
npm run msw:setup
```

This script will:
1. Check if mkcert is installed (and guide you if it's not)
2. Install the mkcert Certificate Authority (one-time per machine, shared across all projects)
3. Generate SSL certificates for `prod.foo.redhat.com` (per checkout, gitignored)

**Important:** After setup, **fully restart your browser** to pick up the trusted certificate.

If you hit certificate errors later, delete the `.pem` files and re-run `npm run msw:setup`.

### Running MSW

```bash
npm run msw
```

Then visit: https://prod.foo.redhat.com:1337/openshift

You should see:
- Console message: `[MSW] Mocking enabled.`
- Mocked API responses in the Network tab

No query parameters needed! The `npm run msw` command automatically enables MSW via environment variable.

## How It Works

### Architecture

When you run `npm run msw`:

1. **Dev server starts** (`fec dev-proxy`) with webpack building to `dist/`
2. **http-server** serves `dist/` on port 8003
3. **Caddy proxy** runs in a container, routing:
   - `/apps/chrome/*` → Chrome server (HCC shell)
   - `/apps/openshift/*` → http-server (port 8003)
   - `/mockServiceWorker.js` → http-server (port 8003) - **required for MSW**
4. **Custom certificates** are mounted into the Caddy container (via `start-with-msw.sh`)
5. **MSW service worker** registers and intercepts API calls

### MSW Activation

MSW activates when **both** compile-time gates are true:

1. `APP_DEVMODE` — set automatically by the dev build (always true during local development)
2. `APP_MSW_ENABLED` — set only when you run `npm run msw` (which passes `MSW_ENABLED=true` to webpack's DefinePlugin)

The service worker then intercepts matching API requests and returns mocked responses.

## Adding Mock Handlers

Edit `src/mocks/handlers.ts`:

```typescript
import { http, HttpResponse } from 'msw';

export const handlers = [
  // Example: Mock authorization endpoint
  http.post('*/api/authorizations/v1/self_access_review', () =>
    HttpResponse.json({
      allowed: false,
      resource_type: 'Cluster',
      // ... other fields
    }),
  ),

  // Add more handlers here
  http.get('*/api/clusters_mgmt/v1/clusters', () =>
    HttpResponse.json({
      items: [/* mock cluster data */],
    }),
  ),
];
```

**Important:** Use wildcard URLs (`*/api/...`) instead of relative paths (`/api/...`) because axios prepends absolute URLs.

## Troubleshooting

### "Unsupported MIME type" error

The service worker script isn't being served correctly.

**Fix:**
1. Stop the dev server
2. Restart: `npm run msw`
3. Hard refresh in browser (DevTools open → right-click refresh → "Empty Cache and Hard Reload")

### Certificate warnings

**Fix:**
1. Run `npm run msw:setup` again
2. Fully restart your browser
3. Clear HSTS for `prod.foo.redhat.com`:
   - Chrome: `chrome://net-internals/#hsts` → Delete domain security policies
   - Firefox: Clear site data in Settings

### MSW not intercepting requests

**Check:**
1. Console shows `[MSW] Mocking enabled.`
2. You started with `npm run msw` (not just `npm run start`)
3. Service worker registered: `chrome://serviceworker-internals/`
4. Handler URLs use wildcard: `*/api/...`

### Container runtime not found

Ensure podman or docker is installed:
```bash
which podman || which docker
```

## Files

### Committed to repo:
- `src/mocks/handlers.ts` - Mock API handlers
- `src/mocks/browser.ts` - MSW service worker setup
- `src/mocks/MSWPlugin.js` - Webpack plugin to copy service worker file
- `public/mockServiceWorker.js` - MSW service worker script (generated by `npx msw init public/`)
- `.caddy/Caddyfile` - Custom Caddy config that uses mkcert certificates
- `setup-msw.sh` - One-time setup script for developers
- `start-with-msw.sh` - Starts dev server, waits for Caddy, mounts certificates

### NOT committed (gitignored):
- `prod.foo.redhat.com.pem` - SSL certificate (generated by mkcert)
- `prod.foo.redhat.com-key.pem` - SSL private key (generated by mkcert)

Each developer generates their own certificates using `npm run msw:setup`.

## Why mkcert?

Browsers require trusted SSL certificates for service workers - self-signed certs don't work even with click-through.

**Without mkcert:** Caddy generates its own certificates which need constant re-trusting in the browser.

**With mkcert:**
- One-time setup per machine
- Certificates valid for ~2 years
- Automatically trusted by all browsers
- Works across all projects on the machine
